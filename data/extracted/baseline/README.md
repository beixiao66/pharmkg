# L4 朴素基线（已冻结）

> 冻结于 **2026-10-13**，代码 commit `7d7d73b`。
> **这个目录一经写入就不再修改**——它是 L4 消融实验的对照基准。

## 为什么先跑这个

决策 #30 / Q6：L4 的第一个动作是跑并冻结朴素基线，之后所有改进
（按小节切分、JSON 约束、两次抽取比对）都对着它比。
**事后补的基线没有说服力**——答辩时会被质疑"你是照着改进结果反推的基线"。

## 「朴素」的准确定义：四个"没有"

| | 基线 | 改进组 |
|---|---|---|
| 输入粒度 | **没有按小节切分**——整篇说明书一次送（最长 48,473 字符） | 按小节送（决策 #30 / Q3） |
| 调用次数 | **每篇一次** `chat.completions` | 同 |
| 输出约束 | **没有 JSON schema**——自由文本 | 强制 JSON |
| 自检 | **没有**——不校验格式、不做一致性比对、不做补救 | 两次抽取比对 |

⚠️ 唯一的"重试"是**网络层重试**（3 次）：只重试"调用没成功"，
**不检查"模型答得对不对"**。内容层面的补救属于改进组，不属于基线。

## 怎么复现

```powershell
$PY = ".\backend\.venv\Scripts\python.exe"
& $PY scripts\extract_baseline.py --dry-run   # 先看规模与成本，不调 LLM
& $PY scripts\extract_baseline.py             # 全量；已跑过的跳过
```

输入是 `data/collected/text/*.txt`（决策 #31 冻结的 36 份），**原样整篇送，不裁剪**。
`run_meta.json` 里逐篇记了 `input_sha256`，可以核对送进去的到底是哪一版文本。

## 顺带量到的一个成本事实

| | 输入 token | 占比 |
|---|---|---|
| 整篇送（本基线） | ≈ **61.3 万**（36 篇合计字符数） | 100% |
| 按小节送（改进组，只送禁忌/注意事项/儿童用药） | ≈ **12.6 万** | **20.5%** |

**基线大约是改进组的 4.9 倍。** 这条对比本身就是论文里"为什么要按小节送"
的一个论据——不只是精度，还有成本。

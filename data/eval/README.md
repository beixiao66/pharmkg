# L4 评测集

> **标好即冻结。** 这 11 份是 L4 唯一的评分依据，**不得进入任何提示词或 few-shot**
> （与决策 #26 同一纪律——否则等于考前透题，消融实验的数字会被答辩质疑到崩）。

## 这份评测集是什么

L4 要从说明书里抽【禁忌】。要算 P / R / F1，就得先有一份"标准答案"。
36 份全标是 2–4 小时的体力活、边际收益低；所以**抽 11 份人工标注**，
其余 25 份只跑不评。

## 抽了哪 11 份、为什么

**分层随机 + 确定性强纳入**，可复现（`seed=20261013`）：

```powershell
& .\backend\.venv\Scripts\python.exe scripts\build_eval_set.py --list
```

| 层 | 【禁忌】长度 | 抽中 |
|---|---|---|
| 1 | 1–23 字 | **托法替布**（强纳入）、克拉屈滨、达沙替尼 |
| 2 | 29–40 字 | 他克莫司、奥希替尼 |
| 3 | 45–90 字 | 伤寒疫苗、多塞平 |
| 4 | 91–160 字 | 阿那格雷、英夫利西单抗 |
| 5 | 184–391 字 | 奥扎莫德、来氟米特 |

**为什么分层**：全随机可能抽不到"禁忌只有 13 字"那几篇，而它们最容易翻车；
只挑最长的又等于对着长文本出题，recall 会虚高。分层保证覆盖 **1 字 → 391 字** 的整个区间。

**为什么还要强纳入托法替布**：它【禁忌】正文只有 `无` 一个字。
分层随机没抽中它，而它是"**原文没有禁忌**"与"**我们没抽到**"会不会混的
**唯一试金石**（决策 #30 / Q5 的 `generic_only`）。标注它约 10 秒，成本可忽略。

## 「一条禁忌」的定义（**决定 P/R/F1 的分母**）

> **按"独立的人群 / 情形"拆开。**

例一（简单）：

```
原文：严重的肝、肾功能损害者、孕妇及长期接触砷或有砷中毒者禁用。
→ 3 条：① 严重的肝、肾功能损害者  ② 孕妇  ③ 长期接触砷或有砷中毒者
```

例二（本评测集里最需要动手拆的一条）：

```
多塞平【禁忌】原文只有一行：
  严重心脏病、近期有心肌梗死发作史、癫痫、青光眼、尿潴留、甲状腺机能亢进、
  肝功能损害、谵妄、粒细胞减少、对三环类药物过敏者。
→ 10 条（每一项单独一条）
```

**为什么不照原句算 1 条**：图谱里每条 `CONTRAINDICATED_FOR` 边对应**一个**
"谁不能用"（决策 #30 的 e：一条禁忌一条边），粒度必须对齐。
照原句算的话，"只抽到 1 条、漏掉另外 9 个情形"会被判**完全正确**——
等于把最容易出的错藏起来。

## 怎么填

文件：[`contraindications_gold.csv`](contraindications_gold.csv)（已按原文每行预填）

| 列 | 填什么 |
|---|---|
| `drug` | 药名，**别改** |
| `n_gold` | ← **你填**：该药一共几条禁忌（同一药的所有行填同一个数） |
| `item_idx` | 序号，拆分后自己重排 |
| `gold_text` | ← **你核**：照抄原文，**别改写** |
| `src_line` | 预填时对应原文第几行，仅供参考 |
| `note` | 提示（如"原文就是「无」"） |

规则：
1. **一条 = 一个独立的人群/情形**（见上面定义），该拆就拆、该并列就并列
2. `gold_text` **照抄原文**——评价的是"有没有抽到"，不是"会不会改写"
3. 原文确实没有禁忌的（托法替布正文只有 `无`）：`n_gold` 填 **0**，并**删掉数据行**
4. 填完跑校验：

```powershell
& .\backend\.venv\Scripts\python.exe scripts\build_eval_set.py --verify
```

校验会检查：11 个药齐不齐、`n_gold` 填没填、**`n_gold` 与实际行数对不对得上**。

# L5 问答链路的问题集

`l5_questions.csv`（28 条，**手工撰写、2026-10-16 冻结**）—— 由 `scripts/build_l5_questions.py` 生成。

**为什么先做它**：实体链接与 Text2Cypher 都要"对着问题量成功率"。问题集不定下来，
后面所有实验都建在流沙上。而按**决策 #26，few-shot 严禁取自冻结的测试集**——
所以顺序只能是"**先冻结问题集，再写提示词**"。

| 意图 | 条数 | 靠什么关系 |
|---|---|---|
| 相互作用 | 5 | `INTERACTS_WITH` |
| 疾病用药 | 5 | `RECOMMEND_DRUG` **正向**（Disease → Drug） |
| 适应症 | 4 | 同一条边**反向**走 ← 最容易写错方向 |
| 禁忌 | 6 | `CONTRAINDICATED_FOR`（只挑 `confidence=high`） |
| 药品信息 | 4 | 节点属性（英文名） |
| 其他 | 4 | **不该给事实**：图谱没有 / 需要澄清 / 完全无关 |

**措辞是人写的，金标准必须"有据可查"**：`gold_cypher` 列是可执行 Cypher，
由 `scripts/verify_l5_questions.py` 逐条跑一遍确认能查出东西。
**"图里到底有没有这个事实"不能靠印象**——这是 L4 那两次栽跟头的教训。

```
$ python scripts/verify_l5_questions.py
  问题 28 条；金标准不成立的 0 条
  ✓ 每条有金标准的问题都能查出东西
```

## 验证时挖出的两个数据质量问题（实体链接的直接输入）

**(1) 同一个名字跨多个标签——全图 1,774 个**

```
类风湿关节炎: [['Symptom'], ['Disease']]
肾阳虚:      [['Symptom'], ['Disease']]
```

`MATCH (:Disease {name:'类风湿关节炎'})` 能查到、`MATCH (n {name:'类风湿关节炎'})`
会返回**两个**节点。实体链接**必须连标签一起选**，否则可能对着 Symptom 节点去查
`RECOMMEND_DRUG`（那条边只从 Disease 出发），查不到还会以为是"数据没有"。

**(2) 简称补全会有多候选，而且夹着截断垃圾**

```
茶碱    → ['茶碱缓释片', '茶碱缓释胶', '茶碱缓释胶囊']   ← 中间那个是**截断的垃圾节点**
卡维地洛 → ['卡维地洛片']                              ← 单候选，可以补
二甲双胍 → ['二甲双胍格列本脲片(Ⅰ)']                     ← ⚠️ 这是**复方**，不是二甲双胍单方
```

三个后果：单候选才敢自动补（`卡维地洛`→`卡维地洛片`）；多候选必须**澄清反问**（§13.3）；
而候选里混着截断垃圾与**复方制剂**，所以"按前缀取第一个"是错的做法——
`二甲双胍` 取到复方片会把两种药的相互作用算到一种药头上。

# L5 尖刀实验 ① · 实体链接结果

`scripts/l5_entity_linking.py`——确定性扫描（最长优先），**不用 LLM**。
意图**直接取问题集里标好的**（刻意分层：否则"没认出药名"与"意图判错"会混在一起）。

## 结果

```
索引      20,610 个节点名（Drug/Disease/Population）· 54,982 个前缀
判分      按 expect 分类

  TP 31  FP 0  FN 0
  P 1.000  R 1.000  F1 1.000
  整条全对：23 / 23（expect=链接）
  歧义题澄清正确：1 / 1（expect=澄清，Q04 茶碱）
```

## 满分必须先证明它不是恒真的——三个对照

只看"1.000"无法分辨"方法好"和"指标不会动"。所以故意做坏三份，让它当场失败：

| 对照 | 做了什么 | P | R | F1 | 整条全对 | 澄清 |
|---|---|---|---|---|---|---|
| （本方法） | 最长优先 + 覆盖门槛 + 多候选澄清 | 1.000 | 1.000 | 1.000 | 23/23 | 1/1 |
| `none` | 什么都不链接 | 0.000 | 0.000 | 0.000 | 0/23 | 0/1 |
| `first` | 前缀**取第一个**候选、不澄清不设门槛 | 0.969 | 1.000 | 0.984 | 22/23 | **0/1** |
| `no-label` | 不按意图过滤标签 | 1.000 | 1.000 | 1.000 | 23/23 | 1/1 |

**前两个对照证明指标会动。第三个对照是失败的——而它暴露了我判分的一个盲点：**

> `no-label` 居然也是 1.000。原因是**判分比的是节点名，而图里同名跨标签的两个节点名字完全一样**
> （`类风湿关节炎` 同时是 `Symptom` 和 `Disease`）。所以"标签选错"这件事，
> **本轮的分层根本量不出来**。
>
> 结论：**标签选择属于第 ③ 步 Text2Cypher**——Cypher 里写 `:Disease` 还是 `:Symptom`
> 才是决定性的。实体链接只负责产出**名字**。本轮不越界判它，但要如实说明这个盲点。

## 三个实测逼出来的规则（每一条都有反例）

1. **提问词汇不参与链接**。图里真的存在一个叫 **``禁忌``** 的节点（垃圾数据），
   于是 `多塞平有哪些禁忌？` 会把它当第二个实体链出来。加一份**提问词汇表**
   （禁忌/注意事项/适应症/英文名…）——注意这是 **L5 自己的提问用语**，
   **不是实体名的同义词表**（后者是本项目明令禁止的）。图里那个垃圾节点该由 L8 清。
2. **自动补全要求前缀覆盖候选名的大部分（≥0.6，且 ≥3 字）**。反例：
   `今天上海的天气怎么样？` 里的 **``今天``**（2 字）是垃圾节点 **``今天应该拉了四次``**（9 字）
   的唯一前缀 → 自动补全把它当实体链了出来。覆盖 0.22 → 拦掉。
   验算：`卡维地洛`/`卡维地洛片`=0.83 ✓；`大环内酯类药物过敏`/`大环内酯类药物过敏者`=0.9 ✓。
3. **顺序：多候选先判"需澄清"，覆盖门槛只管"单候选自动补全"**。
   反过来写会把 `茶碱`（3 个候选，含**截断垃圾** `茶碱释胶`）静默降级成"认不出"——
   而 §13.3 要的是**反问用户**，不是当作没事发生。

> 还有一条**问题集本身的修正**：`茶碱` 那条（Q04）原本把金标准写成一个节点，
> 但问题本身**有歧义**（3 个候选），按 §13.3 正确行为是澄清。
> 于是给问题集补了 `expect` 列（`链接`/`澄清`/`边界`），Q04 标成 `澄清`。
> **补列时重新跑了一遍金标准验证，结论不变（28 条全过）。**

## 「其他」那 4 条：3 条其实链得出实体

```
Q25 阿司匹林能治癌症吗？      链出 癌症
Q26 感冒了吃什么药好？        链出 感冒
Q27 孕妇能吃这个药吗？        链出 孕妇
Q28 今天上海的天气怎么样？     链出 （未链出实体）
```

它们的 `intent` 是当初**凭印象**标的，实测有 3 条能链出实体——说明"其他"这个标注**可能不对**
（`感冒了吃什么药好？` 其实是「疾病用药」）。它们本就不进指标，留待**意图识别那一轮**再定。
Q28 现在正确地什么都没链出来（对照 ② 修好之前它会链到那个九字垃圾名）。

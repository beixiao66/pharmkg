# L4 评测集

> **标好即冻结。** 这 11 份是 L4 唯一的评分依据，**不得进入任何提示词或 few-shot**
> （与决策 #26 同一纪律——否则等于考前透题，消融实验的数字会被答辩质疑到崩）。

## 这份评测集是什么

L4 要从说明书里抽【禁忌】。要算 P / R / F1，就得先有一份"标准答案"。
36 份全标是 2–4 小时的体力活、边际收益低；所以**抽 11 份人工标注**，
其余 25 份只跑不评。

## 抽了哪 11 份、为什么

**分层随机 + 确定性强纳入**，可复现（`seed=20261013`）：

```powershell
& .\backend\.venv\Scripts\python.exe scripts\build_eval_set.py --list
```

| 层 | 【禁忌】长度 | 抽中 |
|---|---|---|
| 1 | 1–23 字 | **托法替布**（强纳入）、克拉屈滨、达沙替尼 |
| 2 | 29–40 字 | 他克莫司、奥希替尼 |
| 3 | 45–90 字 | 伤寒疫苗、多塞平 |
| 4 | 91–160 字 | 阿那格雷、英夫利西单抗 |
| 5 | 184–391 字 | 奥扎莫德、来氟米特 |

**为什么分层**：全随机可能抽不到"禁忌只有 13 字"那几篇，而它们最容易翻车；
只挑最长的又等于对着长文本出题，recall 会虚高。分层保证覆盖 **1 字 → 391 字** 的整个区间。

**为什么还要强纳入托法替布**：它【禁忌】正文只有 `无` 一个字。
分层随机没抽中它，而它是"**原文没有禁忌**"与"**我们没抽到**"会不会混的
**唯一试金石**（决策 #30 / Q5 的 `generic_only`）。标注它约 10 秒，成本可忽略。

## 「一条禁忌」的定义（**决定 P/R/F1 的分母**）

> **按"独立的人群 / 情形"拆开。**

例一（简单）：

```
原文：严重的肝、肾功能损害者、孕妇及长期接触砷或有砷中毒者禁用。
→ 3 条：① 严重的肝、肾功能损害者  ② 孕妇  ③ 长期接触砷或有砷中毒者
```

例二（本评测集里最需要动手拆的一条）：

```
多塞平【禁忌】原文只有一行：
  严重心脏病、近期有心肌梗死发作史、癫痫、青光眼、尿潴留、甲状腺机能亢进、
  肝功能损害、谵妄、粒细胞减少、对三环类药物过敏者。
→ 10 条（每一项单独一条）
```

**为什么不照原句算 1 条**：图谱里每条 `CONTRAINDICATED_FOR` 边对应**一个**
"谁不能用"（决策 #30 的 e：一条禁忌一条边），粒度必须对齐。
照原句算的话，"只抽到 1 条、漏掉另外 9 个情形"会被判**完全正确**——
等于把最容易出的错藏起来。

## 怎么填

文件：[`contraindications_gold.csv`](contraindications_gold.csv)（已按原文每行预填）

# L5 问答链路的问题集

`l5_questions.csv`（28 条，**手工撰写、2026-10-16 冻结**）—— 由 `scripts/build_l5_questions.py` 生成。

**为什么先做它**：实体链接与 Text2Cypher 都要"对着问题量成功率"。问题集不定下来，
后面所有实验都建在流沙上。而按**决策 #26，few-shot 严禁取自冻结的测试集**——
所以顺序只能是"**先冻结问题集，再写提示词**"。

| 意图 | 条数 | 靠什么关系 |
|---|---|---|
| 相互作用 | 5 | `INTERACTS_WITH` |
| 疾病用药 | 5 | `RECOMMEND_DRUG` **正向**（Disease → Drug） |
| 适应症 | 4 | 同一条边**反向**走 ← 最容易写错方向 |
| 禁忌 | 6 | `CONTRAINDICATED_FOR`（只挑 `confidence=high`） |
| 药品信息 | 4 | 节点属性（英文名） |
| 其他 | 4 | **不该给事实**：图谱没有 / 需要澄清 / 完全无关 |

**措辞是人写的，金标准必须"有据可查"**：`gold_cypher` 列是可执行 Cypher，
由 `scripts/verify_l5_questions.py` 逐条跑一遍确认能查出东西。
**"图里到底有没有这个事实"不能靠印象**——这是 L4 那两次栽跟头的教训。

```
$ python scripts/verify_l5_questions.py
  问题 28 条；金标准不成立的 0 条
  ✓ 每条有金标准的问题都能查出东西
```

## 验证时挖出的两个数据质量问题（实体链接的直接输入）

**(1) 同一个名字跨多个标签——全图 1,774 个**

```
类风湿关节炎: [['Symptom'], ['Disease']]
肾阳虚:      [['Symptom'], ['Disease']]
```

`MATCH (:Disease {name:'类风湿关节炎'})` 能查到、`MATCH (n {name:'类风湿关节炎'})`
会返回**两个**节点。实体链接**必须连标签一起选**，否则可能对着 Symptom 节点去查
`RECOMMEND_DRUG`（那条边只从 Disease 出发），查不到还会以为是"数据没有"。

**(2) 简称补全会有多候选，而且夹着截断垃圾**

```
茶碱    → ['茶碱缓释片', '茶碱缓释胶', '茶碱缓释胶囊']   ← 中间那个是**截断的垃圾节点**
卡维地洛 → ['卡维地洛片']                              ← 单候选，可以补
二甲双胍 → ['二甲双胍格列本脲片(Ⅰ)']                     ← ⚠️ 这是**复方**，不是二甲双胍单方
```

三个后果：单候选才敢自动补（`卡维地洛`→`卡维地洛片`）；多候选必须**澄清反问**（§13.3）；
而候选里混着截断垃圾与**复方制剂**，所以"按前缀取第一个"是错的做法——
`二甲双胍` 取到复方片会把两种药的相互作用算到一种药头上。

# L5 尖刀实验 ① · 实体链接结果

`scripts/l5_entity_linking.py`——确定性扫描（最长优先），**不用 LLM**。
意图**直接取问题集里标好的**（刻意分层：否则"没认出药名"与"意图判错"会混在一起）。

## 结果

```
索引      20,610 个节点名（Drug/Disease/Population）· 54,982 个前缀
判分      按 expect 分类

  TP 31  FP 0  FN 0
  P 1.000  R 1.000  F1 1.000
  整条全对：23 / 23（expect=链接）
  歧义题澄清正确：1 / 1（expect=澄清，Q04 茶碱）
```

## 满分必须先证明它不是恒真的——三个对照

只看"1.000"无法分辨"方法好"和"指标不会动"。所以故意做坏三份，让它当场失败：

| 对照 | 做了什么 | P | R | F1 | 整条全对 | 澄清 |
|---|---|---|---|---|---|---|
| （本方法） | 最长优先 + 覆盖门槛 + 多候选澄清 | 1.000 | 1.000 | 1.000 | 23/23 | 1/1 |
| `none` | 什么都不链接 | 0.000 | 0.000 | 0.000 | 0/23 | 0/1 |
| `first` | 前缀**取第一个**候选、不澄清不设门槛 | 0.969 | 1.000 | 0.984 | 22/23 | **0/1** |
| `no-label` | 不按意图过滤标签 | 1.000 | 1.000 | 1.000 | 23/23 | 1/1 |

**前两个对照证明指标会动。第三个对照是失败的——而它暴露了我判分的一个盲点：**

> `no-label` 居然也是 1.000。原因是**判分比的是节点名，而图里同名跨标签的两个节点名字完全一样**
> （`类风湿关节炎` 同时是 `Symptom` 和 `Disease`）。所以"标签选错"这件事，
> **本轮的分层根本量不出来**。
>
> 结论：**标签选择属于第 ③ 步 Text2Cypher**——Cypher 里写 `:Disease` 还是 `:Symptom`
> 才是决定性的。实体链接只负责产出**名字**。本轮不越界判它，但要如实说明这个盲点。

## 三个实测逼出来的规则（每一条都有反例）

1. **提问词汇不参与链接**。图里真的存在一个叫 **``禁忌``** 的节点（垃圾数据），
   于是 `多塞平有哪些禁忌？` 会把它当第二个实体链出来。加一份**提问词汇表**
   （禁忌/注意事项/适应症/英文名…）——注意这是 **L5 自己的提问用语**，
   **不是实体名的同义词表**（后者是本项目明令禁止的）。图里那个垃圾节点该由 L8 清。
2. **自动补全要求前缀覆盖候选名的大部分（≥0.6，且 ≥3 字）**。反例：
   `今天上海的天气怎么样？` 里的 **``今天``**（2 字）是垃圾节点 **``今天应该拉了四次``**（9 字）
   的唯一前缀 → 自动补全把它当实体链了出来。覆盖 0.22 → 拦掉。
   验算：`卡维地洛`/`卡维地洛片`=0.83 ✓；`大环内酯类药物过敏`/`大环内酯类药物过敏者`=0.9 ✓。
3. **顺序：多候选先判"需澄清"，覆盖门槛只管"单候选自动补全"**。
   反过来写会把 `茶碱`（3 个候选，含**截断垃圾** `茶碱释胶`）静默降级成"认不出"——
   而 §13.3 要的是**反问用户**，不是当作没事发生。

> 还有一条**问题集本身的修正**：`茶碱` 那条（Q04）原本把金标准写成一个节点，
> 但问题本身**有歧义**（3 个候选），按 §13.3 正确行为是澄清。
> 于是给问题集补了 `expect` 列（`链接`/`澄清`/`边界`），Q04 标成 `澄清`。
> **补列时重新跑了一遍金标准验证，结论不变（28 条全过）。**

## 「其他」那 4 条：3 条其实链得出实体

```
Q25 阿司匹林能治癌症吗？      链出 癌症
Q26 感冒了吃什么药好？        链出 感冒
Q27 孕妇能吃这个药吗？        链出 孕妇
```

Q28 现在正确地什么都没链出来（对照 ② 修好之前它会链到那个九字垃圾名）。

# L5 尖刀实验 ② · Text2Cypher 结果

`scripts/l5_text2cypher.py`——实体**已给定**（实体链接的输出）、意图也取自问题集，
所以这一轮量的**只剩"会不会写 Cypher"**。判分口径＝**执行结果集比对**（用户拍板）：
比字符串没意义（`{name:'X'}` 与 `WHERE n.name='X'` 完全等价）。

## 结果

```
qwen-plus   temperature=0   few-shot 12 条   24 条里有金标准的 23 条
只读白名单 + 10s 超时 + 500 行上限

  严格（行多重集）  22/23 = 0.957
  宽松（首列值集）  22/23 = 0.957
  歧义题澄清        0/1
```

> ⚠️ **这个数字改过一次，改的是题不是模型，必须说清楚。**
> 第一版 `0.870`，其中两条失败是 **Q15/Q16——我的金标准比问题更严**（见下节）。
> 用户拍板走 **(i) 把策略写进输出契约**，契约改完后重跑得 **0.957**。
> **这不是调参调上去的**：策略从"要模型猜"变成"明说的接口约定"，模型的行为没变，
> 变的是任务的定义。**旧数字 0.870 同样有效，它是"契约未言明时"的成绩。**

三次失败，**性质完全不同**——这一点比数字本身重要：

| 条目 | 现象 | 是谁的错 |
|---|---|---|
| **Q15 / Q16** | 生成 10 行 / 金标准 8 行、5 行：模型**没加** `WHERE r.confidence='high'` | ⚠️ **我的金标准的问题**（见下） |
| Q23 | 问「卡维地洛是什么药」，模型返回 `d.name_en`，金标准返回 `d.name` | 模型（问句本身也确实含糊） |
| Q04 | 该澄清的题，模型**自己编了个 `茶碱`** 去查，而不是反问 | 模型（且暴露 §13.3 的澄清必须发生在生成之前） |

## ⚠️ Q15/Q16 暴露的是**金标准与问题不一致**

我当初把这两条的金标准写成只取 `confidence='high'`——理由是 L4 的边实测约 **33% 假阳性**。
**但问题里根本没提"高置信度"**。用户问「多塞平有哪些禁忌？」，字面正确的答案就是
**全部 10 条**。所以模型返回 10 行**是对的**，是我的金标准比问题更严。

这不只是"两条题判错"的问题：**它意味着测试集里塞进了一条问题没说的策略**，
于是这一轮实际在考"模型能不能猜到我未言明的过滤条件"。**那是坏题，不是难模型。**

**用户已拍板走 (i)**：把策略写进**输出契约**——契约里加一句
"禁忌只返回 `confidence='high'` 的边"，并说明理由（L4 的边约 33% 假阳性，
对用户展示未加区分的边是不负责任的）。金标准不动。

结果：**0.870 → 0.957**，失败从 3 条降到 1 条，剩下的那条是 Q23（模型真错）。
另外两条出路（备记）：(ii) 金标准改成返回全部——与问句字面一致，但结果里会含假阳性边；
(iii) 不动——承认 0.870 是"保守数字"。

**这件事的教训比那 0.087 重要**：测试集里**不能塞问题没说的策略**。
一旦塞了，评测就在考"模型能不能猜到我心里的规则"，而不是考它会不会写 Cypher。
凡是"金标准比问句严"的地方，都得先问一句：**这条限制在问题里说了吗？**

## 关于「输出契约」——不写它的那次崩溃很值得记

第一版提示词**没有写"该返回什么"**。结果模型对着
「一氧化氮和丙胺卡因能一起用吗？」写出了：

```cypher
RETURN d1.name AS drug1, d2.name AS drug2, d1.name AS drug1_cn, …
       d1.name AS drug1_chinese, d1.name AS drug1_cn_name, …（无限重复）
```

**给同一列起无数个别名，一直写到被 max_tokens 截断** —— 退化重复循环。
根因不是"模型笨"，是**任务没定义输出**。

排查过程里踩了两个坑，都记下来：

1. **差点从单次二分得出错误结论**。看着像"markdown 的 `**` 星号触发的"（去掉星号那次
   恰好 90 token 正常结束），但把两次的**完整输出打出来一看**：一模一样，都是那个循环。
   星号是巧合。
2. **`presence_penalty=1.0` 与 `frequency_penalty=1.0` 都无效**（实测）。
   真正有效的是**在提示词里明确禁止**重复，以及**必须设 `max_tokens`**——
   不设的话这个循环会一直写到请求超时，看起来像"接口挂了"。

## few-shot 消融：**零增益**

| 模式 | 严格 |
|---|---|
| full（12 条示例） | 22/23 = 0.957 |
| `--no-fewshot`（只给 schema+契约） | **20/23 = 0.870** |

**在旧契约下两者一模一样（都是 20/23）**；补上"禁忌只看高置信"这条契约后，
full 升到 22/23，而 `--no-fewshot` 仍是 20/23。

读法要小心，**别过度解读**：这个消融总共只跑过两次、样本 23 条，
差异又恰好落在"契约里刚补的那条限制"上——很可能示例的作用就是**把契约里的规则
演示了一遍**。要断言"few-shot 有用/没用"，需要更大的集和更多题型（尤其多实体、
否定句、需澄清），而本集里这类只有 1 条。**如实记下，不下结论。**

> ⚠️ 但注意：这个结论**只在这 24 条上成立**。示例可能在其他题型（多实体、否定句、
> 需要澄清）上有用，而本集里这类只有 1 条。不要把它推广成"few-shot 没用"。

## 不泄题的机械保证

`scripts/build_l5_fewshot.py` 把"不泄题"做成**脚本断言**而不是靠肉眼扫：

```
问题逐字相同：0 条  ✓
实体与测试集重叠：1 个（孕妇）——  重叠不等于泄题，但重叠越少示例越独立
意图覆盖：{相互作用:2, 疾病用药:2, 适应症:2, 禁忌:3, 药品信息:2}
```

筛选标准（四条都要过）：

1. 过只读白名单；2. 能真的执行；3. **返回 ≥1 行**（返回 0 行等于教模型"这样查不到"）；
4. **返回值里至少有图节点名**（"有哪些…"的问句只返回关系属性＝没回答问题）。

第 4 条是实测逼出来的：`丁巴比妥的相互作用有哪些？` 生成的 Cypher 跑得通、返回 170 行，
但**只返回 `r.level`、不返回对方药名**——三条标准全过，语义上却没回答问题。
现在它被机械挡掉。

## 两条被丢弃的种子暴露了「标签选择」问题

```
F05 血瘀体质可以用哪些药？   返回 0 行
F11 肾功能不全的人能用三氧化二砷吗？  返回 0 行
```

两次都是模型**把标签猜错了**：`血瘀体质` 在图里同名跨 `Symptom` / `Disease`（全图
**1,774** 个名字跨标签），而 `RECOMMEND_DRUG` 只从 `Disease` 出发；`肾功能不全` 在
§5 里属于 `Population` 而不是 `Disease`。

**这就是实体链接盲点里预言的那件事**：实体链接只产出**名字**，"用哪个标签"是在
Text2Cypher 这一层决定的。现在它有了实测证据。

## 抖动：三遍逐条完全一致

用户拍板"主数字跑 1 次、另跑 2 次只为量化抖动"。`--repeat 3`：

```
第 1 遍 严格 20/23 = 0.870
第 2 遍 严格 20/23 = 0.870
第 3 遍 严格 20/23 = 0.870
逐条判定完全一致：是
```

`temperature=0` **不保证**逐字相同（这一点常被误解），所以这个测试是有意义的；
实测在 23 条上**连每一条的判定都一模一样**。论文里这是"可复现性"的直接证据。

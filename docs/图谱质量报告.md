## 1. 自环：**112 条**

全部是 `ACCOMPANY_DISEASE`（病 → 自己）：

```
青年上肢远端肌萎缩   -[ACCOMPANY_DISEASE]-> 自己
老年人骨关节炎       -[ACCOMPANY_DISEASE]-> 自己
胃肠道癌             -[ACCOMPANY_DISEASE]-> 自己
```

**判定：确定的错误，可安全删除。** 一个疾病不可能是自己的伴随疾病——这是上游
OpenCMKG 的数据缺陷，不是我们的。自环对查询无害（不会返回错答案），但会污染
"疾病关联"类统计与子图展示。

**检测局限：无。** 这是图论层面确定的，不需要人工复核。

## 2. 剂型分裂：**509 个主成分分裂，涉及 1,243 个药**（占 5,696 的 21.8%）

```
利巴韦林         → 9 个：分散片 / 含片 / 气雾剂 / 泡腾颗粒 / 注射液 / …
盐酸氨溴索       → 8 个：分散片 / 口服溶液 / 口腔崩解片 / 注射液 / 片 / …
阿昔洛韦         → 7 个：乳膏 / 凝胶 / 分散片 / 滴眼液 / 片 / …
```

**判定：这不是 bug，是源数据的固有形状。** 每一个剂型都是**独立注册的药品**，
在 NMPA 有其自己的批准文号。所以"利巴韦林"在数据里**本来就该是 9 个实体**。

**它带来的真问题是"同一主成分被当成不同药"**，因此：

- 图谱**不该**把剂型合并（会丢掉"这是滴眼液还是注射液"这个临床关键信息）；
- **但实体链接必须做归一化**——用户说"利巴韦林"，系统要能想到那 9 个剂型。
  这正是 §13.2 记的"78.1% 中文药名带剂型后缀"的后果，也是 L5 实体链接里
  `AUTOCOMPLETE` 前缀补全存在的理由。

**检测局限：词表驱动。** 后缀表漏一个（如新剂型"植入剂"）就会把一个分裂算成一个
正常药；反过来剥太狠会把不同的药合到一起。所以这个数字是**下界**。

## 3. 拼接垃圾：**形状分三类，但精度差别很大**

### 3.1 截断碎片：24 个（**高精度，基本都是真垃圾**）

```
18AA-Ⅰ   19AA-Ⅰ   C   IV   SP   TP   p   Ⅰ
```

这些是复方氨基酸注射液组分的名字（`18AA-Ⅰ`）被拆出来单独当成了药，
以及罗马数字/单字母的碎片。**判定：应删或合并进母体。**

### 3.2 超长名（≥12 字）：137 个（⚠️ **精度很低**）

抽样前 6 个：

```
40 字  氯硝西泮类似物（注：实际为新型抗癫痫药，中国药典及NMPA标准名为‘森诺巴特’）
35 字  甲型流感病毒A/越南/1194/2004(H5N1)株抗原（甲醛灭活）
34 字  甲型流感病毒A/加州/7/2009(H1N1)株样抗原（丙内酯灭活）
28 字  加巴喷丁类似物（注：实际为‘噻加宾’；按中国药典规范名）
28 字  胰岛素样生长因子-1/胰岛素样生长因子结合蛋白-3复合物
25 字  霍乱弧菌CVD 103-HgR减毒活疫苗抗原（活）
```

**这里必须分开说，否则会得出错结论：**

- **第 2/3/6 条是合法的长名**（疫苗株名天然这么长）。把它们当垃圾删掉是灾难。
- **第 1/4 条是真缺陷**，而且性质很特别：**整理者的注释混进了名字字段**
  （`（注：实际为…标准名为…）`）。这是"脏"的另一种形态——不是截断，是**人写的话
  被当成实体名导入了**。

**结论：`超长` 这个判据精度太低，不能单独作为清洗依据。** 真正的判据应该改成
"名字里含 `（注：` / `实际为` 这类**注释标记**"——那个精度会高得多。
（本次未继续做，因为那属于重写检测器，不是本轮范围。）

## 4. 人名噪声：**0 —— 是真的 0，不是没测**

判据是"名字里含 `医生/教授/主任/医师/先生/女士/氏/院长/博士`"，
**药名 0 个、病名 0 个**。

这个 0 有意义：**§13.4 列的这个人名噪声靶点，是从上游数据描述里继承来的，
在实测数据里不成立。** 报告里要写成"实测为 0"，不能写"未发现"含糊过去。

### ⚠️ 但抽样意外发现了另一类垃圾：纯编码被当成药名

为了兜住"纯人名抓不到"这个局限，额外抽了 2–3 字短名供人眼扫，结果：

```
'21'  '23'  '29'  '2∶1'  '30R'  '4:1'  '9AA'  'C14'  'IV'  'SP'
```

**这些是规格/配比/编码，不是药名。** 它不是"人名噪声"，但同样是**不该成为药物实体
的东西**，而且数量可能不少。

**这条是本报告里"抽样比计数更有用"的最好例子**：计数只回答"有没有带标记的人名"（0），
抽样才让人看见"短名里有一堆纯编码"。

## 5. OOV 实体：**60 个（`source=insert` 且非受控词表）**

按来源：`opencmkg` 62,479 · `ddinter` 1,387 · `insert` **65**

样本：

```
CYP2C9*3*3基因型          CYP3A4酶抑制剂使用禁忌     HIV蛋白酶抑制剂
QTc间期延长               QT间期延长                Waldenström巨球蛋白血症
三唑类抗真菌药过敏         中性粒细胞减少
```

### 这个靶点暴露了 L4 的**根本性问题**

`CONTRAINDICATED_FOR` 的 schema 是 `Drug → Disease/Population`，
但 L4 从说明书抽出来的"禁忌对象"里混着这些**根本不是疾病也不是人群的概念**：

| 样本 | 它其实是 |
|---|---|
| `CYP2C9*3*3基因型` | 基因型 |
| `CYP3A4酶抑制剂使用禁忌` | 药物类别 + 使用场景 |
| `QTc间期延长` | 检查指标异常 |
| `三唑类抗真菌药过敏` | 过敏史 |

**这就解释了 L4 那 33% 假阳性的一部分来源**：不是抽取"抽错了"，而是**抽对了东西、
但那个东西放不进 schema**——只能硬塞成 `Disease` 节点。

**这比"准确率 67%"更能说明问题**：错的不是模型，是**槽位定义**与**抽取目标**没对齐。
真要修，得先定"禁忌对象允许哪几类"（疾病 / 人群 / 基因型 / 检查异常 / 合并用药），
而不是继续调提示词。

**检测局限：只看 `source` 与 `vocab` 两个字段，判不了语义对错**；
上面那张分类表是人工看样本得出的，**不是脚本判的**。

## 7. 本轮结论（可直接进论文）

1. **数字大于真相的地方**：`超长 137` 里多数不是垃圾。**只报数字会误导清洗决策。**
2. **抽样大于数字的地方**：`人名噪声 0` 的抽样反而发现了"纯编码药名"这一类。
3. **最有价值的发现不是计数，是 OOV 那 60 个样本**：它们证明 L4 的假阳性
   有相当一部分来自**槽位定义与抽取目标不对齐**，而不是模型能力。
   ——这一条把"再调提示词"这条死路堵上了，指出了一个必须改 schema 的方向。

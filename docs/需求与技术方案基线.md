## 1. 项目目标与验收标准

**课题**：基于 AI 与知识图谱的医药查询与智能用药系统

**"做完了"的定义**（三条同时满足）：

1. 一个可本地一键启动的 Web 系统，用户能：注册登录 → 自然语言多轮提问医药问题 → 得到**可追溯到图谱证据**的回答 → 添加常服药物到"我的药箱" → 一键检查相互作用风险。
2. 一张自建/融合的中文医药知识图谱，落库 Neo4j，可被 Cypher 查询，含疾病、药物、症状、相互作用、禁忌等关系。
3. 一组**冻结的测试集 + 量化指标**：单轮问答准确率、多轮指代消解成功率、抽取准确率、消融对比（纯 LLM vs 图谱增强）。

### 1.1 明确要做的能力

| 能力 | 说明 |
|---|---|
| ✅ **单轮问答** | 一问一答，系统主入口 |
| ✅ **多轮对话** | 带会话上下文，支持指代追问（"那**它**有什么副作用？"） |
| ✅ **会话持久化** | 会话列表 + 历史消息可回看，刷新/重登不丢 |
| ✅ **用药安全校验** | 基于"我的药箱"的相互作用与特殊人群检查 |
| ✅ **按疾病推荐候选药物** | 只到**药物清单**粒度 + 推荐依据 |
| ✅ **图谱可视化** | 定位为回答的"证据路径展示层"，非独立功能 |

### 1.2 明确不做（范围冻结）

- ❌ 不训练/微调实体识别或抽取模型（用 LLM + 现成数据）
- ❌ 不输出具体剂量/疗程的用药方案（只到**药物清单**粒度）
- ❌ 不做联合用药组合推荐、不做开放域闲聊
- ❌ 不爬取商业医药数据库
- ❌ 不做云端部署（本地 Docker Compose 为准）

## 5. 图谱 Schema 设计（草案）

**节点**

| Label | 关键属性 | 来源 |
|---|---|---|
| `Drug` | `id, name_cn, name_en, aliases[], atc_code` | OpenCMKG + DDInter |
| `Disease` | `id, name` | OpenCMKG |
| `Symptom` | `id, name` | OpenCMKG |
| `Population` | `id, name`（孕妇/哺乳期/儿童/老年/肝功能不全/肾功能不全） | 自定义枚举 |
| `Food` / `Department` / `Check` | 保留，用于图谱可视化丰富度 | OpenCMKG |

**关系**

| 关系 | 方向 | 属性 | 来源 |
|---|---|---|---|
| `RECOMMEND_DRUG` | Disease → Drug | — | OpenCMKG `disease_recommand_drug` |
| `COMMON_DRUG` | Disease → Drug | — | OpenCMKG `disease_common_drug` |
| `HAS_SYMPTOM` | Disease → Symptom | — | OpenCMKG |
| `INTERACTS_WITH` | Drug ↔ Drug | `level(Major/Moderate/Minor/Unknown), mechanism, description, management, alternative_drug, citation` | DDInter |
| `CONTRAINDICATED_FOR` | Drug → Disease/Population | `source, evidence` | 说明书抽取 |
| `CAUTION_FOR` | Drug → Population | `level, source, evidence` | 说明书抽取 |
| `SAME_AS` | Drug ↔ Drug | `confidence` | 实体对齐产物 |

> **主键策略**：`Drug` 以**中文通用名**为主键，商品名与英文名入 `aliases`，避免同一药散成多个节点。

## 6. 核心流程设计

### 6.1 问答链路（多轮 + Text2Cypher）

```
用户提问（携带 conversation_id）
  → ⓪ 查询改写【多轮关键步骤】
        输入：最近 N 轮对话 + 当前问题
        输出：一个自包含的完整问题
        规则：若当前问题已含药物实体 → 跳过改写，直接进入下一步
  → ① 意图识别：相互作用 / 适应症 / 疾病用药 / 禁忌 / 药品信息 / 其他
  → ② 实体链接：别名词典精确匹配 → 向量相似度兜底 → 置信度阈值判定
        （低于阈值 → 触发澄清反问，绝不硬猜）
  → ③ Text2Cypher：注入 schema + few-shot 示例 → 生成 Cypher
        → 白名单校验（仅允许 MATCH/RETURN，禁止写操作）→ 超时 + 条数上限
  → ④ 执行查询，取回结构化事实
  → ⑤ 生成回答：仅基于查询结果，禁止外推；无结果时明确回答"图谱中无相关记录"
  → ⑥ 落库：持久化 {原问题, 改写后问题, Cypher, 证据, 回答} 到 message 表
  → ⑦ 返回：回答 + Cypher + 证据子图 JSON + 免责声明
```

> **为什么不让 LLM 直接基于历史生成 Cypher**：历史 Cypher 会污染当前生成，导致错误率上升且难以定位是哪一轮引入的问题。查询改写把"多轮"折叠成"单轮"，使 ③④⑤ 三步完全复用单轮逻辑。

### 6.2 多轮对话与会话管理

**数据表设计**

```sql
conversation(id, user_id, title, created_at, updated_at)
message(id, conversation_id, role, content,
        rewritten_query,        -- 改写后的自包含问题（调试与评测的关键证据）
        cypher,                 -- 实际执行的 Cypher
        evidence_json,          -- 证据子图
        created_at)
```

**实现要点**

- `rewritten_query` **必须落库**——它既是调试依据，也是评测多轮指代消解是否成功的直接证据。
- 会话标题由首条问题自动生成（取前 20 字即可，不必额外调 LLM）。
- 上下文窗口用**最近 N 轮**（建议 N=3）而非全量历史，控制 token 成本。
- 改写失败的降级策略：若改写超时或返回空 → 直接用原问题走单轮链路，不阻断用户。

### 6.3 用药安全校验（"我的药箱"）

```
用户药箱 [药A, 药B, 药C]
  → 检查两两组合：MATCH (a)-[r:INTERACTS_WITH]-(b)
  → 按 level 排序（Major 优先），输出机制 + 处理建议 + 替代药
  → 叠加特殊人群检查（若用户填了人群标签）：CONTRAINDICATED_FOR / CAUTION_FOR
  → 前端以"风险卡片 + 图谱子图"呈现，全部附免责声明
```

### 6.4 说明书抽取管线（离线）

```
① 选样：从 DDInter 中统计出现在 Major 级相互作用里频次最高的 N 种药（数据驱动选样）
② 采集：NMPA 官网逐条说明书，限速、限量、记录 URL 与采集日期
③ 抽取：LLM + 强制 JSON 输出，槽位 = {禁忌, 特殊人群慎用, 注意事项}
④ 质检：同一文本两次抽取比对 → 不一致条目送人工；随机抽 100 条人工核对算准确率
⑤ 入库：对齐到已有 Drug 节点，写入 CONTRAINDICATED_FOR / CAUTION_FOR
```

## 7. 评测方案

| 评测项 | 数据 | 指标 |
|---|---|---|
| 实体抽取准确率 | 随机抽 100 条说明书抽取结果人工核对 | Precision / Recall / F1，错误分类（漏抽/错配/幻觉） |
| 药名映射质量 | 抽 200 个 DDInter 药名 | 映射准确率 + **覆盖率**（1833 个英文药名能对上多少中文药） |
| 单轮问答效果 | 自建 100–200 条测试问答集 | 答案准确率、实体链接命中率、Cypher 执行成功率 |
| **多轮指代消解** | **测试集中独立的多轮子集（30–50 组连续追问）** | **改写成功率、指代消解准确率、末轮回答正确率** |
| 消融对比 | 同上测试集 | 纯 LLM vs 图谱增强 LLM；单轮 vs 多轮 |
| 图谱规模 | Neo4j 统计 | 节点数、边数、覆盖药品种类数 |

> **关键纪律**：测试集必须**先于系统完成前构建并冻结**，否则会不自觉地按系统已有能力出题（自己出题自己考，必被追问）。
> **多轮子集设计要点**：必须包含三种指代类型——代词指代（"它/这个药"）、省略指代（"那布洛芬呢"）、话题延续（"还有别的吗"），并标注标准改写结果。
> **可引用基线**：CH-DDI 论文报告中文 DDI 关系抽取 F1 为 **78.43%**，可作为你抽取效果的参照物。

## 9. 风险登记表与降级预案

| 风险 | 概率 | 影响 | 预案 |
|---|---|---|---|
| 中英药名映射覆盖率低 | 高 | 药箱认不出用户输入的药 | 尽早量化覆盖率；别名词典 + 拼音/模糊匹配兜底；覆盖率如实写入论文局限 |
| Text2Cypher 复杂问题生成错误 | 高 | 答非所问 | 白名单校验 + 执行失败重试 + 澄清反问 + 降级为子图检索 |
| **查询改写把指代改错** | 中 | 多轮回答整体偏题 | 落库 `rewritten_query` 便于定位；已含实体时跳过改写；改写结果做实体合法性校验 |
| 说明书采集受阻 | 中 | 禁忌/特殊人群缺失 | 缩减药品种类；只做 Major 级最高频的 20 种；实在不可得则明确标注为局限 |
| LLM 幻觉出图谱中不存在的关系 | 中 | 医疗信息错误 | 强制"仅基于查询结果生成"；无证据时回答"无记录"；输出必附 Cypher 证据 |
| 答辩现场无网络 | 中 | LLM 调用失败 | 缓存高频问答结果做离线降级；准备演示录屏作为兜底 |
| 数据处理无限打磨导致拖延 | 中 | 中期无成果 | P0 结束即冻结数据处理；每个阶段必须有"可演示状态" |

**本周内必须完成**：

1. 安装 Docker Desktop，起一个 Neo4j 容器，浏览器打开确认可访问
2. 下载 OpenCMKG（`triples.txt`、`entities_dict.txt`），**打印前 20 行确认字段格式**
3. 下载 DDInter 的 8 个 CSV（[下载页](https://ddinter.scbdd.com/download/)），**确认列名**
4. 写一个最小导入脚本：OpenCMKG 三元组 → Neo4j
5. 在 Neo4j Browser 里跑通一条查询：`MATCH (d:Disease)-[:RECOMMEND_DRUG]->(dr:Drug) WHERE d.name CONTAINS '高血压' RETURN dr LIMIT 10`

**完成标志**：能在 Neo4j 里查到"高血压 → 推荐药物"的真实结果。这就是开题报告"可行性分析"一节最有力的证据。

## 12. 答辩必被问到的问题（预先准备）

1. **"这张图谱是你建的吗？"** → 答：骨架来自公开图谱（OpenCMKG），我做的是多源融合、实体对齐、LLM 抽取补齐禁忌与特殊人群——这是明确的增量工作。
2. **"你怎么保证 LLM 不胡说？"** → 答：Text2Cypher 只依据图谱事实生成，无证据时不作答，且每条回答附 Cypher 与数据来源。
3. **"图谱方案比纯 RAG 好在哪里？"** → 答：消融实验数据 + 可解释性（证据可追溯到具体边）+ 相互作用检查这类需要结构化推理的任务，纯文本 RAG 做不了。
4. **"多轮对话怎么做的？"** → 答：查询改写前置层把多轮折叠成单轮，改写结果落库可审计；不是让 LLM 直接维护对话状态，因此不会随轮次增加而退化。
5. **"医疗责任怎么规避？"** → 答：系统定位为用药信息查询工具，不输出剂量建议，所有结果附免责声明，要求用户遵医嘱。
6. **"数据来源合法吗？"** → 答：DDInter CC BY-NC-SA 4.0（学术非商业用途）、OpenCMKG 学术用途、说明书来自 NMPA 公开渠道，均已在论文中署名并说明使用范围。

## 2. OpenCMKG 实测

### 2.1 `entities_dict.txt` —— 单行 Python 字面量

整个文件是**一行** Python dict 字面量，1.47 MB 全在第一行，必须用 `ast.literal_eval` 解析。

| 类型 | 实体数 | 样例 |
|---|---:|---|
| `producer` | 16,772 | 帅乐氟哌噻吨美利曲辛片、南通百益麝香壮骨膏 |
| `disease` | 14,726 | 左边身子疼、鼻塞严重、大便不尽 |
| `symptom` | 12,578 | 纤毛结构缺陷、背也疼、体重降了28斤 |
| `food` | 4,846 | 黄芪茶、火腿鸡块粥 |
| `drug` | 4,289 | 盐酸二甲双胍肠溶片、谷氨酰胺 |
| `treatment` | 598 | 手术治疗为主,若失去手术时机,可药物支持性治疗 |
| `department` | 54 | 风湿免疫科、神经内科 |
| **合计** | **53,863** | |

⚠️ **没有 `check` 类型**——但 `triples.txt` 里有 39,416 条 `disease_need_check`。
所以基线 §5 把 `Check` 列为节点类型这件事，只能从三元组现场收集，**没有别名词表可用**。

⚠️ **1 处裸标识符 `nan`**：上游把 pandas 的缺失值直接 `str()` 写进了文件，
导致 `ast.literal_eval` 抛 `ValueError`。这是上游的质量缺陷，已在本项目中兼容处理并记录。

### 2.2 `triples.txt` —— 解析陷阱（**L1 最容易踩的坑**）

- 编码 UTF-8，LF 换行，**无表头**，格式为 `头实体,关系,尾实体`
- 354,755 行，全部可解析，**0 行重复**，474 条自环

**关键**：字段本身含逗号时会**加双引号**，但只给需要的字段加。三种真实形态：

```
百日咳,disease_need_check,"耳,鼻,咽拭子细菌培养"          ← 尾部带引号
"跖骨,趾骨骨折",disease_has_symptom,疲劳                  ← 头部带引号
"小儿人类疱疹病毒6,7,8型感染性疾病",disease_has_symptom,疱疹
```

三种解析方式的实测后果：

| 解析方式 | 有效三元组 | 后果 |
|---|---:|---|
| `line.split(",")` | 352,584 | **静默丢掉 2,171 行**（0.61%） |
| `line.split(",", 2)` | 354,755 | 数量对了，但**内容错位**——头部带引号的行被切成 4 段，造出 `趾骨骨折"` 这种不存在的关系名，污染 13 类关系统计 |
| **`csv.reader`** ✅ | **354,755** | 全部正确 |

> **教训**：`split(",", 2)` 这种"看起来能救回来"的写法最危险——它不报错，
> 但把错误藏进了关系字段里。**必须用 `csv` 模块**，并把"逗号数 ≠ 2 的行数"作为质量指标留下来。

### 2.4 数据质量问题（有证据，不是"可能有"）

骨架图谱**不干净**。三类问题，都有具体条目可查：

**① 人名与口语描述混进了医学词汇表**

| 噪声条目 | 性质 | 出现在 |
|---|---|---|
| `毓卓` | 人名 | **55 个疾病**的症状位 |
| `闫鹏辉` | 人名 | 15 个疾病的症状位 |
| `左边身子疼`、`肚子一痛`、`刀口有点疼` | 患者口语 | `disease` 词表 |
| `体重降了28斤`、`背也疼` | 患者口语 | `symptom` 词表 |

关键点：`毓卓`、`闫鹏辉` **在 `entities_dict['symptom']` 里是"合法"的**——
说明污染发生在**词表构建阶段**，不是后来插入的。这解释了 QAKG 的数据来源：
它源自 39 健康网 / 寻医问药的患者问答，医生署名和患者口语被一起抓了进来。

**② 同一主成分因剂型分裂成多个实体**

| 主成分 | 分裂条数 | 变体 |
|---|---:|---|
| 利巴韦林 | 7 | 胶囊 / 颗粒 / 滴眼液 / 泡腾颗粒 … |
| 阿昔洛韦 | 7 | 乳膏 / 滴眼液 / 胶囊 / 分散片 … |
| 格列吡嗪 | 5 | 分散片 / 片 / 缓释片 / 控释片 |

→ 做药名映射前**必须先归一化**（剥离剂型、盐形式），否则同一个药会被算成多个实体，
覆盖率会被系统性低估。

**③ 拼接垃圾**

`盐酸普萘洛尔片盐酸地尔硫`、`佛山)药业伤科跌`、`6-二磷酸果糖"`、`C颗粒"` ——
明显的爬取截断/拼接产物。

**④ 量化指标**

| 指标 | 数值 |
|---|---:|
| `disease_has_symptom` 症状实体数 | 6,673 |
| 只挂在 1 个疾病下的症状 | 1,333（20.0%） |
| 不在 `entities_dict['symptom']` 里的症状 | 938（14.1%） |
| 自环（头 == 尾） | 474 |

> **对本项目的意义**：这不是坏消息，是**好消息**。
> 基线 §12 里"这张图谱是你建的吗"的答辩要点，现在有了硬证据支撑：
> 骨架有多源、有噪声、有实体分裂问题，而我要做的是**多源融合 + 实体对齐 + 质量校验**。
> L8（图谱质量校验）从"锦上添花"升级为"必要的、可量化的增量工作"。

### 2.5 `SameAs` 关系 —— 白送的实体对齐数据

17,977 条 `SameAs` 三元组，涉及 17,351 个不同实体。样例：

```
下肢疼痛  ↔  下肢困痛不适
下肢疼痛  ↔  腿会疼
下肢疼痛  ↔  腿疼
下肢疼痛  ↔  右腿痛
```

**这是一条现成的同义词/实体对齐链路**，可以直接支撑 L4 的实体链接：
做监督信号、做评测参照、或至少做 few-shot 示例。覆盖率有限（79% 的实体能在
`entities_dict` 里找到类型，40,133 个实体未被任何 `SameAs` 引用），
所以只能当**金标准子集**用，不能当完整词典。

### 2.6 `manual_annotation.csv` —— 现成的实体对齐金标准

| 项 | 值 |
|---|---|
| 列名 | `实体1,实体2,标注结果`（带 BOM） |
| 条数 | 852 |
| 标注分布 | 1（同一实体）560 条 / 0（不同实体）291 条 / 空 1 条 |

```
妊娠合并糖尿病    | 妊娠期糖尿病        → 1
急性淋巴细胞性白血病 | 急性淋巴细胞白血病   → 1
体质性低血压      | 体位性低血压        → 0    ← 注意：名字像，但标注为"不同"
```

> **用途**：基线 §7 里"药名映射质量"要抽 200 个药名人工核对——
> 现在有一份**他人已标注的 852 条实体对齐数据**，可直接用来评测实体链接模块，
> 比自己临时标注更可信、更省时间。这是本次体检最大的意外收获。

### 2.7 药名格式 —— 回答基线 §10 问题 2

|---|---:|

| **带剂型后缀** | 3,350（78.1%） |

## 3. DDInter 实测

### 3.1 列名 —— 只有 5 列（**推翻基线的核心假设**）

8 个文件列名完全一致：

```
DDInterID_A, Drug_A, DDInterID_B, Drug_B, Level
```

```
DDInter58,Aluminum hydroxide,DDInter582,Dolutegravir,Major
DDInter112,Aprepitant,DDInter582,Dolutegravir,Minor
```

⚠️ **没有 `mechanism` / `description` / `management` / `alternative_drug`。**

基线 §5 的 `INTERACTS_WITH` 边定义了 6 个属性，§13 的 L2 验收标准要求
"能查到等级、机制与处理建议"——**后三者根本不在 CSV 里**，
只存在于 DDInter 网站的药物详情页（需另外爬取）。

### 3.2 规模与去重

| 指标 | 实测 | 基线声称 |
|---|---:|---:|
| 原始记录总数 | 222,383 | 236,834 |
| **去重后无序药对** | **160,235** | — |
| 重复记录 | 62,148 | — |
| 药物 ID 数 | 1,939 | 1,833 |
| 同一 ID 多种写法 | 0 | — |

**分片规则未解**。两个假说都被实测否定：

- 假说一「按药名首字母分片」：各文件首字母命中率只有 3%–22% → **否定**
- 假说二「按药物分片（每药只属一个文件）」：只有 4.2% 的药只出现在 1 个文件 → **否定**

字母 code 的确切含义未知（可能是药理分类，但没有公开对照表）。
**但这对工程没影响**：不管 code 是什么，都必须按 `frozenset(Drug_A, Drug_B)` 去重，
否则 62,148 条重复记录会变成图谱里的重复边。

### 3.3 严重程度分布

| Level | 记录数 | 占比 | 去重后 | 占比 |
|---|---:|---:|---:|---:|
| Moderate | 130,367 | 58.6% | 96,675 | 60.3% |
| Unknown | 47,182 | 21.2% | 29,813 | 18.6% |
| Major | 33,896 | 15.2% | 26,914 | 16.8% |
| Minor | 10,938 | 4.9% | 6,833 | 4.3% |

⚠️ **`Unknown` 占 21.2%**，意味着五分之一以上的相互作用**没有严重程度**。
L6（用药安全校验）不能假设每条边都有等级，必须显式处理 `Unknown`。

### 3.4 药名写法 —— L2 验收标准的坑

| 搜索词 | DDInter 中的匹配数 |
|---|---:|
| `aspirin` | **0** |
| `acetylsalicylic` | 1 → `Acetylsalicylic acid` |
| `warfarin` | 1 → `Warfarin` |

**DDInter 里没有 "Aspirin" 这个名字**，阿司匹林对应 `Acetylsalicylic acid`。
华法林 ↔ 乙酰水杨酸实测查得 **Major** 级（对应 L2 验收标准）。

含 Warfarin 的记录 1,256 条，其中 Major 级 173 条。

> **教训**：药名映射表必须按 DDInter 的**实际写法**建（含 `(topical)` 这类修饰、
> 用 `Acetylsalicylic acid` 而非 `Aspirin`），不能凭常识或英文词典推。

## 4. 基线断言复核

| 指标 | 基线声称 | 实测 | 结论 |
|---|---:|---:|---|
| OpenCMKG 疾病实体数 | 14,726 | 14,726 | ✅ 一致 |
| OpenCMKG 药物实体数 | 4,289 | 4,289 | ✅ 一致 |
| OpenCMKG 三元组数 | 354,755 | 354,755 | ✅ 一致 |
| OpenCMKG `disease_recommand_drug` | 60,621 | 60,621 | ✅ 一致 |
| DDInter 药物数 | 1,833 | 1,939 | ⚠️ 差 +106 |
| DDInter 相互作用对数 | 236,834 | 222,383 | ⚠️ 差 −14,451 |

OpenCMKG 四项全部实测吻合，说明基线 §3 的数据源表是可靠的。

DDInter 两项有差异，原因是**口径不同**，论文里必须写清楚用哪个：
- **药物数**：1,833 来自官网介绍页；CSV 实测 1,939 个 ID（含复方、外用、停产药）。以 CSV 为准。
- **相互作用对数**：236,834 与 CSV 原始记录数 222,383 也不符；
  去重后的**无序药对**只有 160,235。三个数字口径完全不同。
